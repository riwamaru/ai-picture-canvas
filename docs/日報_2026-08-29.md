## 2. 不具合：ダウンロードが「遷移」になっていた

報告：「生成画像をダブルタップしても最大表示されない。ダウンロードを押してもダウンロードされずに最大表示されて、前の画面に戻れない」

### 原因

署名付き URL を `<a download>` に入れてクリックさせていた。
**`download` 属性はクロスオリジンの URL では無視される**仕様で、署名付き URL は Supabase（別オリジン）を指すため、ブラウザはダウンロードせず**その URL へ遷移**していた。画面いっぱいに画像が出て、アプリへ戻れなくなる。

### 直し方

- 同一オリジンの `/api/jobs/[id]/download` を追加し、`Content-Disposition: attachment` を付けて返す。iOS Safari を含めて確実にダウンロードになる
- 画像は非公開のまま。認証と RLS で持ち主を確認してから返す。日本語ファイル名は RFC 5987 で載せる

### ついでに足したもの

- **拡大表示（ライトボックス）**：候補が小さく中身を確認できなかった。閉じる手段を 4 つ用意（× ／ 背景タップ ／ Esc ／ 端末の戻る）。「戻れない」が発端なので、閉じられない状況を作らない
- **モバイル対応**：確定 UI は 3 カラム固定（`height:100vh; overflow:hidden`）でメディアクエリが 1 つも無く、スマートフォンでは操作できなかった。900px 以下で縦積みにし、操作する順（加工内容 → 生成 → 履歴）に並べ替え。デスクトップの見た目は変えていない

### 実装中に自分で作った不具合（1 件）

`.lightbox` と `.lightbox-body` の両方に閉じる処理を置いたため、背景タップでイベントが伝播して `history.back()` が 2 回走り、**拡大表示だけでなくアプリごと前のページへ戻っていた**。閉じる処理は最外の要素にだけ置き、内側は伝播を止める形に直した。

## 3. 除去を Gemini へ回す — 同じ方式では回せない

### Gemini にマスク画像は渡せない

実際にモデル一覧を取って確認した。**現行の Gemini 画像モデルは全て `generateContent` のみで、inpaint / mask 対応は 1 つも無い。** 対応していた `imagen-3.0-capability-001` は 2026-06-30 に停止済み。

### semantic masking で回す

- 元画像
- **除去範囲をマゼンタの輪郭で囲んだ目印つき画像**
- 位置と面積を述べた文章（9 分割の位置表現＋外接矩形の座標）

の 3 つを渡し、目印そのものは描かないよう明示する。

### 実測（OpenAI を意図的に失敗させて経路を通した）

| 項目               | 結果                                     |
| ------------------ | ---------------------------------------- |
| 生成               | 成功（google / semantic_mask）           |
| 目印の写り込み     | **0 画素**                               |
| 元画像との平均画素差 | **3.5**（PoC の目安で再圧縮ノイズ相当）   |
| 出力サイズ         | 768×1024 → **896×1195**                  |
| 所要／実費         | 18.6 秒／$0.138                          |

### ★ inpaint とは別物である

|                  | OpenAI（inpaint）      | Gemini（semantic masking） |
| ---------------- | ---------------------- | -------------------------- |
| 範囲の伝え方     | マスク画像を API へ    | 目印つき画像＋説明文       |
| マスク外の不変   | **仕組みで担保**       | **保証なし**               |
| 出力サイズ       | 指定どおり             | モデルが決める             |

出力サイズが変わるため、**「マスク外が画素単位で不変」は Gemini では原理的に成立しない。** PoC の判定基準 T-02（マスク外に変化なしが 8 割以上）は OpenAI の結果にしか適用できない。

混同を防ぐために 3 つ手を打った。

1. `job_images.edit_method`（`inpaint` / `semantic_mask` / `instruct`）に方式を必ず記録
2. 画面のバッジに「**マスク指定**」「**範囲を説明**」と表示
3. 管理者設定に「除去も Gemini へ回す」のスイッチ（切れば OpenAI 単独の結果だけを見られる）

### 位置づけ

PoC の日報は「T-02 は測定不能が確定」としており、これは「マスク編集として測れない」という意味である。今回の semantic masking はその判断を覆すものではない。**測定の代替ではなく、体験環境で「とりあえず何か結果が見られる」ための道**。測定に使うときはスイッチを切る。
