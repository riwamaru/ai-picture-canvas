## 2. 仕様書 4.7 をどう実装したか

| 仕様書                              | 実装                                                                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 4.7.1 保存先は共有ドライブに限定    | サービスアカウントは自身の容量を持たず、マイドライブへは書けない。設定画面に「接続を確認する」を置き、保存前に共有ドライブ内かを判定 |
| 4.7.1 フォルダ名ではなく ID で解決  | `drive_folders.folder_id` が一次情報。改名しても紐付けは切れない                                                          |
| 4.7.2 ① 同時作成                    | `drive_locks` のリース行で「DB 確認 → Drive 作成 → DB 保存」の区間を覆い、取得判定を `pg_advisory_xact_lock` で直列化。取得後にもう一度 DB を見てから作る |
| 4.7.2 ② Drive 作成後に DB 保存失敗  | Drive を叩く**前**に `drive_folder_attempts` へ試行を記録。決着しなかった行が孤児候補として管理画面に出る                |
| 4.7.2 ③ DB に ID があるが Drive で削除 | 404 を検知して作り直し、DB を更新し、Slack で管理者へ通知（過去画像は復旧できないため記録を残す）                     |
| 4.7.2 ④ Drive API の一時失敗        | 「Drive 未同期」として記録するだけで UI は止めない。画像は Supabase に残る。日次バッチと手動で再送                     |

### なぜロックを「テーブルの行」で持つのか

仕様書は「DB のアドバイザリロックまたは行ロック配下で行う」としている。
しかし Postgres のロックは**トランザクションの終わりで必ず解放され**、真ん中に Drive への HTTP 呼び出しが挟まる区間全体は覆えない（PostgREST 経由ではトランザクションを跨げない）。

そこで区間全体はリース行で覆い、その**取得判定そのもの**をアドバイザリロックで直列化した。
リースには 180 秒の期限を付けてある。**期限が無いと、関数が途中で落ちたときにそのキャストが二度と保存できなくなる。**

実 DB で 6 通り（取れる／他人は取れない／他人は解放できない／解放後に取れる／別キーは待たない／期限切れは奪える）と、`anon` / `authenticated` から関数を呼べないことを確認した。

## 3. 高解像度の再生成（STEP 5 ①）

選んだ 1 枚を 2K で作り直し、確定画像とする。`final_images` を新設。

- **引き伸ばしではなく作り直し**（仕様書 5.4 の 2 段階生成）。選んだ候補と完全に同じ絵にはならない。画面にもそう書いた
- **ドラフトを作ったのと同じプロバイダ・方式を最初に試す。** 別モデルで作ると「選んだものと違う絵」が確定画像になる
- 条件（強度・バリエーション・テンプレート）はドラフトと同一。`jobs` に残した入力から組み直す
- **必ず `reserve_generation` を通す。** 迂回する経路は作らない
- 1 セッションにつき確定は 1 枚（`final_images.job_id` に UNIQUE）

### 費用について先に伝えたこと

2K は `gpt-image-2` の quality:high で **1 枚 約 $0.85**（1024×1024 で $0.211、2048×2048 はその 4 倍の画素数）。
日次予算の既定 $10 では確定 11 回で使い切る。押す前に金額を確認させ、管理画面から 1K へ落とせるようにした。

→ 翌回の実測で、OpenAI が拒否して Google で作られる現状では **2K でも $0.136** と分かった（Google は 1K と 2K が同額）。

### こちらの判断でやめたこと

前回はドラフトを直接 Drive へ送れるようにしていたが、再生成が無かったための代用だった。
仕様書 STEP 5 は確定した 1 枚だけを Drive へ入れる設計なので、**ドラフトの Drive 保存は外した**（両方入ると Drive を見てどれが確定画像か分からなくなる）。

## 4. 実装したが、この日は動かせなかったもの

Drive との実通信と 2K の実生成は、**資格情報（サービスアカウント）と共有ドライブが無く、一度も走らせていない。**
